CommerceIQ / Data extraction

From browser crawlers
to async APIs.

Launching a browser is an expensive way to retrieve a structured response. I moved heavy extraction workloads into asynchronous REST services, cutting their compute costs by roughly 90%.

Explore the architecture

Where the savings came from

A browser runs a page and its supporting resources. An API service can request the data directly. Moving extraction to that boundary removed browser overhead from the affected workloads.

Keeping the pipeline dependable

Across the wider ingestion system, my Airflow DAGs split validation, deduplication, and scheduling into stages. That separation makes it possible to reason about bad inputs and duplicate work independently. The pipelines handled over four million daily requests with 99.5% reliability.

CommerceIQ / Developer tooling

From schema to service.

Each new integration used to take five days to onboard. I built a Node.js and Express generator that translates live API schemas into deployable modules. Onboarding fell to a day and a half.

Engineering detail

The schema describes the shape of the API. Using it as the generator’s input moved repeated integration work into one service and cut the time engineers spent assembling each module by 70%.

Personal project / In development

CodeShare.

I’m building a collaborative editor where people can edit together in a shared room. The interesting problem is keeping a room’s changes consistent when clients connect to different servers.

Explore the design

React provides the editor interface. The design uses STOMP over WebSockets for continuous updates, room-scoped state to isolate sessions, and Redis Pub/Sub to carry edit events between Spring Boot instances.
